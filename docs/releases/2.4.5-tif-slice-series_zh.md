# TaxaMask v2.4.5：散片 TIF 选择导入与内嵌模型配置补充修复

发布日期：2026-08-14

这是 v2.4 系列的小版本更新。它新增了从一个切片目录中只选择研究所需 `.tif` / `.tiff` 文件、再合成为一个三维标本工作体的入口，并将 `v2.4.4` 发布后已经进入公开 `main` 的内嵌智能体模型目录与修复面板凭据修复统一纳入版本标签。

## 散片 TIF 导入

- TIF 工作台现在提供两个含义明确的入口：`导入完整 TIF 体数据`用于已有的多页 TIFF，`合并多个 TIF 切片`用于文件夹中逐张保存的单层 TIFF。
- 研究者可以在文件选择窗口中只选需要分析的切片。程序按文件名中的数字进行自然排序，例如第 2 张排在第 10 张之前，再沿 Z 轴合成为一个标本。
- 导入过程逐张读取并写入磁盘映射工作体，不会先把整组切片全部装进内存；这对 CPU、核显和内存有限的设备尤其重要。
- 项目中新增 `tif_slice_series_manifest.json`，记录源文件、实际顺序、尺寸、数据类型和灰度语义，便于之后核查本次三维重建使用了哪些原始切片。
- 工作体仍先写入 `.building` 临时路径，完整写入并校验后才成为正式体数据；中断或失败不会留下看似可用但实际不完整的标本。

## 数据一致性保护

- 所选文件必须是单页、单通道灰度 TIFF，并具有一致的宽高、位深和灰度解释。
- 程序会拒绝多页文件、RGB/palette 图像、尺寸或数据类型不一致的混合序列，以及 `MINISBLACK` 与 `MINISWHITE` 混用的序列，避免在没有提示的情况下改变切片亮暗含义。
- 文件名和 TIFF 元数据通常不能可靠给出真实 Z 间距，因此程序不会自动猜测。研究者仍需根据扫描参数或实验记录确认体素 Z 间距，避免后续三维形态比例失真。

## 内嵌智能体补充修复

- 同一协议和 URL 的网关现在按模型 ID 合并全局与项目模型目录，项目同名模型保持更高优先级；切换回项目默认模型后，不会再从选择列表消失。
- 不同网关端点的模型与凭据继续隔离，不会互相串用。
- 修复面板保存的 API Key 改为写入独立用户恢复配置，重新打开面板后可继续读取；恢复配置不能覆盖 TaxaMask 的 Hooks、权限或源码保护策略。
- 内嵌 Ant Code 版本为 `1.3.0-taxamask.2`。旧版本修复面板中保存但未被读取的 Key，需要在更新后的面板中重新保存一次。

## 真实数据验收

- 使用 `Raw Tiffs-Living Ant-1_0.4X-LE1-40kv-2w-3s-11.998-1601-DR.zip` 中全部 1024 张真实切片完成验收。
- 每张切片为 `1024 x 1024`、`uint16`、`MINISBLACK`；合成工作体为 `1024 x 1024 x 1024`，约 2.147 GB。
- 导入生成的是磁盘映射工作体；首张、第 512 张和末张均与源 TIFF 逐像素一致。
- SQLite 项目关闭后重载成功，Qt 工作台可直接打开第 `512/1024` 张非空预览，没有把整个 2 GB 工作体一次性载入内存。
- 进度显示保持单调前进，覆盖逐张读取、工作体完成和项目保存阶段，不再在接近完成时向后跳动。

## 升级说明

更新后请完整退出并重启 TaxaMask。已有完整多页 TIFF 项目不需要转换；散片目录请使用新的`合并多个 TIF 切片`入口，并在选择文件前确认切片命名能够反映预期的 Z 顺序。
