# TaxaMask v2.4.2：大型 TIF 导入与预览响应修复

发布日期：2026-08-05

这是 v2.4 系列的小版本维护更新，针对大型 TIF 位于低速机械硬盘、TaxaMask 项目位于 SSD、设备仅有核显或使用 CPU 依赖时出现的长时间界面无响应。修复集中在导入落盘、切片查看、整卷 3D 首屏和项目切换的前后台边界，不改变源 TIF、标注数据角色或训练逻辑。

## 研究工作流影响

- 导入进度现在区分读取、刷新工作卷、定稿和保存项目。只有这些阶段全部成功后才显示 100%，不会在磁盘仍忙时让研究者误以为导入已经结束。
- 工作卷先写入项目中的 `specimens/<specimen_id>/working/image.ome.zarr.building`，完整刷新并关闭后才原子提升为 `image.ome.zarr`。断电、磁盘错误或程序异常不会留下一个被项目误认成完整体数据的正式目录；重试会清理明确的半成品。
- 大体数据的 Z/Y/X 切片读取、灰度归一化和标签叠加改为后台执行。连续拖动切片时只完成最新请求，不再要求机械盘依次读完所有已经越过的位置。
- 导入完成后先显示 Z 切片，不再自动开始整卷 3D。研究者确认切片可读后仍可手动进入三维体渲染。
- 大整卷首次 3D 预览在后台准备。源体数据超过 512 MiB 时，OpenGL/核显首屏最大边限制为 512，CPU fallback 最大边限制为 128；明确选择的 ROI 和局部高细节检查不受这个首屏限制。
- 切换个体、关闭项目或释放体数据时，会等待切片与 3D 后台读取停止后再关闭内存映射，避免旧任务继续访问已经释放的数据。
- 导入和 working-volume 生成期间的进度窗口不再提供无效的关闭按钮。本版本没有把“关闭窗口”包装成中途取消；磁盘写入仍会完成或按异常路径回滚。

## 能填补的漏洞

- 修复“后台导入已经结束，但切片/3D 的大块读取又回到界面线程”的后台化缺口。
- 修复核显/OpenGL 路径绕过后台预览、在界面线程同步构建大纹理的缺口。
- 修复快速切换时旧预览与新预览并行争用磁盘、CPU 和内存的任务覆盖缺口。
- 修复关闭进度窗只隐藏界面、实际任务仍继续运行所造成的状态误导。
- 修复工作卷写到一半就使用正式目录名，异常后可能留下半成品的恢复缺口。
- 修复项目切换时后台读取与内存映射释放之间的竞态风险。

## 仍然存在的硬件边界

机械硬盘读取数 GiB TIF 的真实耗时不会被软件消除，核显或 CPU fallback 的三维画质与速度也不会等同于独立显卡。本版本保证重任务不应长期占住 Qt 界面线程，并优先给出可操作的切片或低分辨率 3D 首屏；完整数据读取仍受硬盘吞吐、系统内存、Windows 页面文件和 OpenGL 驱动影响。

CPU 版 PyTorch/nnU-Net 依赖只决定深度学习计算设备，不会强制关闭 Qt/OpenGL。没有独立显卡的设备仍可能通过核显进入 OpenGL 渲染。`xhost.exe` 不是 TaxaMask 源码或启动脚本启动的进程；若它异常占用 CPU，应作为设备环境的独立问题排查。
