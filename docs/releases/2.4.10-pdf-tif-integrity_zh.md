# TaxaMask v2.4.10：PDF 到 2D 与 TIF 链路完整性修复

发布日期：2026-08-24

`v2.4.10` 是 v2.4 系列的数据安全与工作流连续性修复版本。它承接 `v2.4.9` 发布后的全面复核，修复 PDF 提取结果进入 2D 工作台、TIF 模型草稿导回、真值提升、自动保存和项目切换中的失败边界。

本版本不修改项目数据格式、标注算法或训练模型，也没有把机器裁决写成产品默认的人工真值来源。`manual_truth` 仍是受显式确认门禁保护的训练数据角色，不是操作者身份认证或专家质量背书。

## PDF 到 2D 链路

### PDF 身份与产物命名空间

- PDF 产物范围标识与 SQLite `UNIQUE(file_path)` 使用同一精确来源身份，避免名称清洗、截断、同名文件或当前工作目录变化造成跨 PDF 碰撞。
- 每次提取使用独立运行命名空间保存图像、review batch 和原始响应；失败只清理本次运行创建的文件，不删除上一轮有效证据。
- 旧版 import-ready 产物只在数据库归属唯一时清理。大小写差异、平台路径别名或权限错误存在歧义时保守保留并记录告警。

### 数据库与文件系统事务

- PDF 主提取在数据库提交前失败会回滚 SQLite，并关闭文档句柄；不会发布未提交运行的 import-ready 文件。
- import-ready 导出采用 staging、publish、rollback 三阶段更新。复制、manifest 写入或发布失败时保留上一版完整投影。
- 发布前验证所有数据库引用的源图存在；缺图会使投影失败，不再静默跳过后覆盖旧导出。
- 重试已提交结果时若发现投影源图缺失，会自动放弃仅投影恢复并执行完整重提取；旧数据库记录在新事务提交前保持可回滚。
- 发布成功但 Windows 文件锁等原因导致临时备份清理失败时，已提交投影保持成功，同时返回恢复目录和清理告警，供用户确认后处理。

### 部分成功语义

- 数据库已经提交、但 import-ready 投影失败时，单 PDF 结果为 `partial_success`，整次 agentic 运行标为 `partial`。
- `tools/agentic/extract_figures.py` 对完整成功返回 `0`，对部分成功返回 `2`，对失败返回 `1`。只检查进程退出码的调用方不再把未完成投影误判为通过。
- agentic CLI 默认保存 import-ready 所需的图像；可用 `--no-save-images` 明确关闭，也可用 `--no-resume` 强制重提取。两项选择都会写入 run index。
- 中英文 PDF 界面都会明确说明数据库已保存、投影需重试；源图完整时同一 PDF 重跑只修复投影，源图缺失时自动执行完整重提取。

## TIF 标注与真值链路

### 路径隔离

- `working_edit`、`manual_truth`、part/reslice truth 和模型草稿源均按平台真实路径身份检查。
- 写入前拒绝同一路径、符号链接或目录别名，以及祖先/后代目录重叠，防止异常项目布局让工作编辑覆盖训练真值。
- macOS 常见的大小写不敏感文件系统会通过已存在物理祖先识别尚未创建子路径的大小写别名；大小写敏感文件系统上的合法同级目录仍保持独立。

### 体数组与项目记录事务

- 模型草稿复制和真值提升把体数组替换、内存项目记录及 SQLite 保存作为协同事务处理。
- SQLite 或项目保存失败时，目标体数组、内存记录和数据库一起回滚；复制到 `working_edit` 不推进 `manual_truth` 谱系。
- 数据已经提交但旧回滚备份清理失败时不撤销新数据；项目内原子、有界的维护 sidecar 和运行日志都会保存告警，项目重开后仍可发现，避免把清理问题伪装成事务失败。维护记录使用进程锁和 dirty-only 合并，两个进程并发追加或达到 100 条上限时不会用旧快照挤掉对方的新告警；损坏、超限、未知 schema 或项目身份不符的旧 sidecar 会先隔离到有界的 `.rejected` 槽，再写入当前项目的新记录。

### 未保存编辑与自动保存

- 模型草稿导回失败后可恢复脏切片、修订号、撤销/重做历史、工具模式和材质选择。
- 待恢复快照属于另一项目、specimen 或部位时会阻止导回，并恢复原有自动保存计时器。
- 若只知道编辑层为 dirty、却无法确定改动切片，工作台会阻止破坏性草稿覆盖，要求先保存或明确丢弃；不再用空快照声称可恢复未知像素。
- 草稿复制、重新加载和快照恢复连续失败时，待恢复快照继续按未保存数据处理；在成功恢复或明确处理前，关闭、项目切换和样本切换不会静默清除它。
- 自动保存等待超时会保留仍在运行的线程、worker 和任务引用，并阻止同步保存、项目关闭或切换。
- 取消未保存提示或保存失败时会恢复此前运行的自动保存计时器；异步手动保存随后失败时也会恢复已启用的自动保存。
- 保存元数据成功后才清除 dirty 状态；元数据失败继续保留脏切片恢复信息。

### 项目生命周期

- 关闭 TaxaMask、创建项目或打开另一项目时，TIF 未保存提示中的“取消”会中止整个切换。
- TIF 保存、真值提升、导入、后端线程和 task manager 任务运行期间，项目不能被替换。
- TIF manager 的创建和加载使用内存状态事务；目标项目无效或创建失败时恢复原项目状态，成功载入新项目也会清空旧项目尚未提交的数据版本 UUID，避免跨项目污染完整性谱系。
- 2D manager 的创建和加载同样使用运行态快照；普通项目切换采用轻量引用快照，只有分阶段修改才复制受影响记录，避免大型标注项目产生全量双份内存。
- 新项目 manifest 即使在原子发布后才抛出异常，也会与本次创建的 SQLite artifacts 一并清理，不留下指向缺失数据库的入口。若配置、视图刷新、模型预载、画布或日志等后续 finalize 步骤失败，只回滚经路径、内容和文件身份确认属于本次创建且调用前不存在的 manifest/SQLite/WAL/SHM/journal；预存项目和用户目录内其他文件保持不变。同一窗口实例只有持有完整事务签名时才能同名重试、恢复隔离文件或继续未完成删除；重启后的 marker 只用于提示人工复核，不授予自动加载、移动或删除权限。成功 finalize 会先写入不可回滚的 `committed` 终态再尝试删除 marker。
- 从开始页、2D、TIF 或 STL 打开另一项目时，三个 manager、活动项目字段、最近项目配置、页签、当前图像、列表缓存和画布共同进入切换事务；配置、日志、局部视图刷新、模型预载或画布任一步失败都会恢复切换前状态。
- TIF 工作台关闭过程中若渲染器、数组或界面清理抛错，会从仍然有效的项目 manager 重建工作台并中止切换，不留下半清空界面；目标项目刷新失败时还会恢复原 specimen、完整体/部位 scope、part 和 reslice 选择。
- STL rendered-view 注册先在内存分阶段完成，所有界面 finalize 成功后才执行唯一一次项目保存；失败按受影响图像回滚。SQLite 重载时从稳定 provenance 重建 `view`、`specimen_id`、`metadata_ref` 和 `review_mode` 镜像，不扩展项目 schema。

## 发布门禁

- `v2410_release_audit` 聚合 152 个精确、唯一且可加载的 PDF/TIF/项目事务/发布回归 test ID；历史名称 `v249_post_release_audit` 保留为同一清单的兼容别名。
- GitHub Release 工作流要求 Windows、Ubuntu、macOS Python 3.12、Embedded Agent Center 和 Paper Distill Skill bundle 五个指定检查全部存在且成功，不能在慢任务尚未注册时提前打 tag。
- 发布请求版本必须与 `CITATION.cff` 一致，且只能存在一份匹配版本的 release note；说明 H1 同时作为描述性 GitHub Release 标题。

## 本地验证

冻结前候选在 Windows `taxamask` Conda 环境运行：Python 3.10.19、PySide6 6.10.1、torch 2.7.1+cu118，Qt offscreen/software 用于自动化 GUI 回归。

- `v2410_release_audit`：152 项。
- PDF、TIF 工作台、项目事务、生命周期和本地化相关模块：460 项。复现命令：

  ```powershell
  python -m unittest tests.test_pdf_figure_filename tests.test_tif_project tests.test_tif_workbench tests.test_tif_annotation_workflow_controller tests.test_tif_project_lifecycle_controller tests.test_main_window_stage4_project_lifecycle tests.test_ui_localization
  ```

- 默认验证入口动态收集 1,806 次测试调用、1,779 个唯一 test ID；27 次重复来自既有 `round5_local_axis_risk` 分组。
- cleanup-warning 安全 I/O 与 TIF 项目回归在 Windows 和 WSL/Linux 各运行 89 项并通过；Windows 跳过 1 项仅适用于 POSIX 目录句柄的故障注入。
- Python 语法编译、YAML 解析、`git diff --check` 和发布敏感文件扫描纳入候选检查。

上述数字只有在最终冻结提交上的对应命令全部通过后才构成本地证据。Windows、Ubuntu 和 macOS 的结论必须引用该提交产生的新 GitHub Actions 运行；不能沿用 `v2.4.9` 的 CI。

## 数据影响与兼容性

- 启动或升级不会自动重写原始 PDF、TIF、标注数组、模型权重、API Key 或已有项目数据库。
- 已有 2D 和 TIF 项目不需要格式迁移。
- import-ready 清理告警和 TIF 提交后备份清理告警可能留下派生目录，需要在确认新数据可用后人工删除。无法解析的 TIF 维护 sidecar 最多保留一个同目录 `.rejected` 隔离文件，供排查后处理。
- 未保存编辑恢复快照只存在于当前进程内，不是跨崩溃的持久恢复日志。TIF 已提交体数组的备份清理告警另行写入项目内 `logs/tif_volume_cleanup_warnings.json`，最多保留 100 条；该维护记录用于发现残留备份，不是标注恢复快照。

## 证据边界

本版本证明的是软件工作流连续性、事务边界和真值隔离，不证明少量样本训练的定位器或分割模型具有生物学准确性。自动化 UI 点击或智能体裁决实验必须在实验记录中明确标注其机器来源，不能表述为人工或独立专家真值。

## 升级说明

更新后请完整退出并重启 TaxaMask。Windows 用户继续双击 `启动TaxaMask.bat`；WSL/Linux 用户使用 `启动TaxaMask.sh`。已有项目、TIF 工作体和已保存标注无需重新导入。
