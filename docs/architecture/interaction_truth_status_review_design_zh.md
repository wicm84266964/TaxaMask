## 1. 证据边界与既有结论校正

本文的“源码确认”表示能在当前代码中定位条件、写入或显示路径，不表示已在运行中的 TaxaMask 窗口重现。本文没有声称实际研究数据受到污染，也没有将自动测试当作生物学准确性的证据。

1. **SAM 的问题是生成提示与确认写入不一致。** 人工框选或点选触发 SAM 的回调进入普通多边形保存入口，结果默认记录为人工确认。它不是“所有 SAM 路径都会确认”：VLM 与主工作台子部位专家的自动生成路径已经显式保存为草稿。
2. **2D 训练预检已有逐部位信任过滤。** 未确认或信任记录冲突的部位会被排除。画布与列表没有正确表达这些差异；被错误记录为 confirmed 的生成结果则不能靠这道过滤自动辨别出来。
3. **已确认不等于保证可参加本次训练。** 图片可读性、多边形有效性、目标部位范围和训练方案仍会影响准入。界面不能把一个绿色状态直接叫“整张图完全可训练”。
4. **当前规则不支持随意增加“人工绘制，未确认”标签。** `training_truth.py` 的合法记录校验不接受 manual 来源配 draft 状态。若以后引入手工草稿，需要另行设计；本次不能只在显示层虚构这种状态。
5. **TIF 可编辑层保存不是自动提升为真值。** 已确认的是部位可编辑层保存会写入 `predicted_pending_review`；这不足以证明所有手工标注都被误当成预测，或普通保存会覆盖 `manual_truth`。
6. **Agent 与 Blink 的两处疑点在留档补查中得到源码确认。** Agent 语言刷新只按进程存活显示就绪；Blink 在专家文件缺失但仍有指定记录时返回 ready。具体视觉表现与完整操作路径仍需运行验收。
7. **导出并非始终只有无限进度条。** 开始时为不确定进度，收到非零总量后会切为数量进度。确实没有取消按钮，且成功后会自动打开目录并弹窗；是否增加取消属于体验与写入恢复设计，不能简单加一个按钮。

关联依据：[研究数据安全与真值策略](data_safety_and_truth_policy_zh.md)、[既有 Agent 交互与工作台布局设计](agent_workbench_ux_optimization_design_zh.md)。本文记录新的修复计划，不改写既有设计稿中的历史实施记录。

## 3. 2D 标注：让生成、保存和确认相互一致

### 3.1 R01：SAM 默认保存为待复核结果

**现状与影响。** `on_sam_mask_generated()` 把结果交给 `on_polygon_completed()`；后者去除 `Auto-Annotated` 占位描述，并调用未显式指定信任状态的 `update_label()`。当前默认分支会写入 manual、confirmed、manual_edit。研究者只是框选或点选触发模型，尚未看见生成结果时，结果就已经获得确认资格。

**拟修方案。** 推荐继续使用“生成草稿”的产品含义，修正生成结果的保存分支。只改文案为“立即确认”虽然改动较小，却要求用户在结果出现前承担确认责任，不作为推荐方案。

1. 将 SAM 生成回调与手工绘制完成的保存意图区分。可共用底层写入函数，但必须显式传入来源、复核状态和接受方式，不能靠描述文本或 `box`/`auto_box` 推断。
2. SAM 点选、框选结果均保存为草稿；框是模型提示输入，其存在不能使轮廓自动获得人工确认状态。
3. **第一轮复用现有 AI 草稿来源，不新增枚举。** 当前合法 AI 来源已包含 `model_prediction`、`vlm_first_mile`、`blink_expert`。主工作台 SAM 应显式写入其中已有且语义最接近的草稿来源（优先 `model_prediction`），`review_status=draft`，`accepted_via` 为空，并接入现有通过草稿、清除草稿、训练预检路径。不得向 `update_label()` 传入尚未登记的新字符串。
4. 若以后需要把“工作台 SAM 辅助”和“训练模型预测”分开审计，再单独设计 `sam_assisted` 一类来源。那是后续持久化契约变化：必须同步合法来源、AI 草稿识别、通过草稿、清除草稿、SQLite/JSON 往返和旧版打开行为。旧版应拒绝或排除不识别来源，不能把新草稿静默解释成历史人工标注。第一轮不做这件事。
5. 生成完成后展示“已生成待复核轮廓”，提供“确认此部位”和现有当前图/批量确认入口。确认后才更新训练信任记录；“已保存草稿”与“已确认”分别反馈。
6. 覆盖已有确认部位前，明确显示图像、部位和替换影响，并保存可恢复的旧状态。模型失败、空结果、项目已切换时保留原标注；继续使用既有异步任务上下文保护。
7. 手工绘制完成仍沿用现有人工确认规则，并在工具提示中说明。手工修改 AI 草稿是否继续视为确认，需在实现前列出实际编辑入口；第一轮不凭显示层新增一套“手工草稿”规则。

**操作代价。** SAM 辅助标注会多一次看结果并确认的步骤。允许按部位或当前图确认以控制操作量，但普通保存、自动保存、切图、切语言都不能代替确认。

**历史数据。** 已有 SAM 结果可能与手工标注共用 manual 来源，不能可靠追溯来源。升级不得批量把旧 confirmed 降为 draft，也不得宣称已自动找回全部历史 SAM 结果。新规则只约束升级后的新生成结果；历史复核需要有来源证据和用户选择。

### 3.2 R02、R03：共用状态解释，按部位展示，按图片汇总

**拟修方案。** 增加一个供画布、图片列表和启动页复用的轻量状态解释层，读取 `resolve_part_training_trust()` 的结果和几何内容。不能另写一套通过描述文本猜测确认状态的规则。

| 内容 | 建议主标签 | 辅助说明 |
|---|---|---|
| AI 草稿多边形 | 待复核 · SAM / VLM / 模型 / 子部位专家 | 已保存；尚未确认 |
| 仅有自动框 | 仅框 · 待生成轮廓 | 不能作为本次多边形训练标签 |
| 仅人工 ROI 或收缩起始框 | 辅助框 | 保留具体用途，不笼统称 AI 草稿或训练真值 |
| 合法 confirmed 多边形 | 已确认 | 详细来源显示“人工绘制”或“AI 结果经人工确认”；训练资格由预检决定 |
| 元数据冲突或几何无效 | 需检查 | 显示原因与下一步，不显示成功色 |
| 历史兼容的人工记录 | 历史人工标注 | 按既有兼容规则解释；不虚构来源或确认日期 |

画布用文字、线型和颜色共同表达状态；选中部位通过加粗、顶点或外圈强调，避免继续用同一种绿色同时表示“选中”和“通过”。保留来源框的区分，并增加小图例。轮廓拥挤时仅展开选中部位的详细标签，保持原图可辨认。

图片存在混合部位，内部采用互斥类别以避免重复计数：**需检查 → 已确认与待处理混合 → 仅已确认 → 仅草稿 → 仅辅助框 → 未标注**。按此顺序归类，每张图只进入一个类别；同一图片的部位计数可在详情中展开。上述“待处理”包括草稿和仅框，不代表所有对象都是 AI。类别之和必须等于项目图片数 N。当前筛选数量单独写明，不能和项目总数混用。启动页复用同一统计，不再把任意 `parts` 说成“已有人工标注”。

**首屏展示。** 六类互斥归类是内部计数规则，不是文件列表的第一视觉。第一轮列表和画布主状态只区分三种研究者能扫到的情况：

- 已确认（可含历史人工标注；不表示整图已通过本次训练预检）
- 待复核（草稿、仅框，以及已确认与待处理混合）
- 未标或需检查（无有效标注，或元数据/几何冲突）

完整六类计数放在列表摘要、展开区或启动页详情。窄屏时摘要折行，不把六类标签并排塞进每个文件名。

**性能约束。** 状态解释只读取已加载或按需获取的标注元数据；局部修改只刷新受影响图片。磁盘完整性、全量几何和模型契约检查仍放在训练预检，不能为了显示绿色在每次选图时扫描整个项目。

**训练预检补齐。** 保留当前逐部位过滤，补齐“未确认部位”“信任记录冲突”原因的中文表达；分别报告图片数与部位数。若一张图只有部分部位符合要求，说明哪些部位会进入当前训练方案，不能显示“整图全部通过”。

### 3.3 R10、R14：提交和撤销必须保留确认边界

这两项都涉及实际写入，不能归入纯颜色优化。它们应分开实施和回归：R10 与 R01 同属生成/提交确认边界，R14 是恢复路径，不要和 SAM 保存缠在同一轮失败分析里。

**Blink 提交（R10，随 A1）。** `apply_to_global()` 的确将局部结果映射回原图，并通过普通写入替换目标部位。建议按钮改为“确认并写回主图”，展示目标图片、部位以及“将替换已有轮廓”或“新增轮廓”。有已有确认内容时提供明确替换确认和可恢复旧状态。仅改了框而沿用旧多边形的分支也要列入核查，避免无意改变原轮廓的信任状态。

**撤销/重做（R14，随 A2）。** 当前只记录 polygon 字典，不记录对应信任状态，恢复时又逐部位发出普通完成信号。实施前须验证“图上同时有草稿和人工标注，修改一个部位后撤销”的场景。拟将一次编辑表示为受影响部位的前后状态，包含几何、框、相关描述及信任信息；恢复通过专用路径完成，不将所有恢复出的草稿当作新手工完成确认。对撤销后消失的部位也要同步删除，不能只重放仍存在的部位。

### 3.4 R09、R11：按钮和下一步提示使用同一份条件

专家文件缺失、专家未指定、路由禁用和未配置是不同情况。`expert_model_missing` 即使仍有指定记录，也不能返回可执行的 ready；显示“指定的专家文件缺失”，禁用自动标注，保留“重新指定专家”和“训练专家”的修复入口。检查内置及外部后端的有效性条件，不能把外部专家强行按内置权重路径判断。

选择分组标题时保留其“非可标注部位”的性质，固定提示“请选择一个具体部位后绘制”，同步刷新 Blink 条件和画布工具可用性。不能静默继续向先前部位写入，也不能只清空部位却让关联按钮仍显示可执行。

## 4. TIF/CT：区分工作层、人工真值和本次训练资格

### 4.1 R04、R13：统一研究语言，保留内部存储契约

首先提取可复用的状态和原因翻译函数，让标本树、部位树、右侧摘要、训练页使用相同解释。已有 `_format_train_ready_reasons()` 的映射可作为基础，移到共享显示层，避免工作台依赖训练面板私有方法。

| 内部值或术语 | 拟显示文字 | 说明 |
|---|---|---|
| `not_started` | 尚未开始标注 | 不表示图像一定已能预览 |
| `cut_pending_labeling` | 已切出，待标注 | 已有部位数据，不代表有真值 |
| `predicted_pending_review` | 编辑结果待核验 | 默认用这句。只有记录里确有模型/预测来源证据时，才显示“预测结果待核验”。手绘保存后带上该内部码，不得因此改口称预测 |
| `verified_train_ready` | 已核验 | 当前训练资格另由 readiness 检查说明 |
| `manual_truth_missing` | 缺少人工核验的训练真值 | 下一步直接指向实际按钮“核验为训练真值” |
| `working_volume` | 工作体数据 | 用于查看、标注和派生处理的图像体 |
| `working_edit` | 编辑工作层 | 普通保存写入这里，不等于确认真值 |
| `editable_ai_result` | 可编辑结果层 | 详情按来源说明 AI 预测或人工修正 |
| `manual_truth` | 人工核验的训练真值 | 详情保留内部角色名以便审计 |
| `raw_ai_prediction_backup` | 原始预测备份（只读） | 显示不可编辑原因 |
| `specimen` / `Material` | 标本 / 材料标签 | 不改标本名称、材料 ID 或标签含义 |

未知状态不能一律转译为“已完成”，应显示“状态待识别”并在详情保留原码。自定义材料名称、分类单元名称、外部工具协议字段不做强制中文替换。

第一轮只修显示映射，不重命名 `system_status`、数据角色或历史项目记录。显示层不得根据中文标签反向改写存储值。进一步核查新建手工部位标注、预测后修正、重切片标注三条保存链：若确有来源信息丢失，再单独设计可追溯来源字段。

标本、部位、重切片的统计单位必须分开。启动页不能只列标本数就暗示覆盖了全部部位训练样本；对于仅有部位真值的项目，应显示部位/重切片数量或明确“此处仅统计整标本”。普通显示使用已有缓存或轻量检查，完整标签 ID 扫描保留在核验与正式训练预检。

### 4.2 R12：覆盖数量与执行目标一致

当前摘要的 selected 只数勾选行，而 overwrite 数遍当前表所有行。推荐拆为“列表内 N 项；已选择 M 项；本次会替换其中 K 项的可编辑结果”，K 必须来自最终选择解析结果。

显示统计、确认弹窗和任务提交应使用同一份已选目标集合，覆盖部位、重切片和整标本模式。改变过滤、全选、取消勾选或任务就绪状态后立即刷新。保持现有只覆盖可编辑层、保护训练真值的边界；本次没有证据证明执行层会覆盖未选中的对象。

### 4.3 待运行核查：导入与切片读取提示

“已加载”和“正在后台读取切片”可以分别描述标本登记与当前切片；两者同时存在未必是错误，但必须标明对象。拟统一为：标本已登记 → 工作体数据准备中 → 工作体数据可用 → 当前切片读取中/可查看。快速切换切片时仅当前请求更新状态，不能由旧请求写回“已加载”。

大体积 TIF 下是否真的出现长期冲突或无响应尚未验证。应使用专门验证体数据和现有后台读取实现测试，不能为了消除文案冲突改回全体数据同步读取。

## 5. 启动中心与 Agent：当前项目和可用状态分别说明

### 5.1 R06：进入工作流之前说明写入目标

目前 `_open_or_create_startup_project()` 创建或加载 `_startup` 默认项目；`enter_image_workflow()` 直接切到当前内存中的 2D 工作台；“继续上次”则根据 `last_project_path` 打开项目。它们是三种独立行为，不能通过同一份“最近项目”文案掩盖。

**拟修方案。**

1. 区分“无正式研究项目”“当前 2D 项目”“当前 TIF 项目”“最近使用项目”和“刚离开的工作台”。卡片分别显示各自名称，工作台顶部持续显示实际写入项目。
2. 没有正式 2D 项目时，“进入 2D/STL”进入新建/打开选择页；取消后停留在启动中心，不产生标注写入。所有入口复用协调器的同一检查，包括菜单和 Agent 工作台路由。
3. 有已打开的正式 2D 项目时，显示“返回 2D：项目名”；“继续上次：项目名（TIF/2D）”保持另一种明确动作。返回启动中心时保留刚离开的工作台身份。
4. 第一轮可保留底层空启动项目以兼容初始化，但它不能伪装成正式研究项目，也不能显示成“尚未选择研究项目”或“暂无最近项目”却仍可静默写入。若当前内存项目就是 `_startup` 空项目，入口应写明“尚未打开正式 2D 项目；启动占位项目仅用于程序初始化”。既有 `_startup` 中若已有图像或标注，显示“启动项目中有待整理内容”，提供打开检查和保存为正式项目的恢复路径，不删除、不自动覆盖。
5. 取消新建或打开之后，不得把后续标注、导入或训练写入 `_startup` 占位项目。是否进一步去掉空项目的磁盘创建属于后续初始化改造。正式项目另存应复用项目管理服务，核对图片引用和相关资产，不能直接复制一个 manifest 就宣称迁移完成。

**操作代价。** 首次进入会多一次新建/打开选择；已打开正式项目的返回动作保持直接。更清楚的项目身份用于避免把新研究标注写进遗忘的默认项目。

### 5.2 R05：Agent 状态只由运行事实推进

已有 `_running_state` 及状态信号应作为基础，不再从 `is_running()` 推断整个页面已就绪。进程存活只用于判断能否停止进程；面板可交互、健康检查通过、页面失败是另外的事实。

| 状态 | 主显示 | 行为 |
|---|---|---|
| stopped | 未启动 | 可以启动；不能停止 |
| starting | 正在启动 | 禁止重复启动；可以取消启动/停止 |
| running | 可以使用 | 满足当前浏览器或内嵌模式就绪条件；可重新加载和停止 |
| stopping | 正在停止 | 等待停止完成，避免重复操作 |
| error | 启动或页面加载失败 | 显示简短原因和重试；若进程仍存活，保留停止入口 |

主状态、控制台和按钮由同一运行状态生成。切语言只重译状态与错误消息，不改变状态值、不把错误重置为 ready。项目统计刷新同样不得重写 Agent 生命周期。

名称按对象统一：入口页叫“启动中心”，其中助手区域叫“TaxaMask 助手”；“启动助手/停止助手/询问助手”保持一致。Ant Code 作为嵌入组件名称保留在关于、运行详情与诊断中。无需把软件内所有不同对象机械地改成同一个名字，也不改 standalone 或嵌入版本标签。

## 6. PDF：分开任务结果、人工复核和导入状态

### 6.1 R07：现场求助应从当前阶段继续

新手入口可继续使用分阶段规划。已有 PDF 工具内的求助建议叫“带上当前 PDF 状态询问助手”，读取当前页签、输入目录、输出数据库状态、最近一次任务结果和复核进度，选择当前阶段；缺少信息时才回到前序步骤。

当前 `get_agent_context()` 已携带页签和目录，但 `settings_question_focus`、`pdf_acquisition_stage` 固定为第 0 阶段。拟修为结构化阶段和待解决事项，不在提取中或结果页重复宣称“尚待确认有没有 PDF”。不能只按页签推断任务已完成，也不能为构造上下文重新跑提取任务。

现场卡片只描述当前研究任务、参数是否配置和必要状态，不默认变成源码排错要求。保留 API key 不进入提示文本的边界。直接打开 PDF 工具是有效入口，无需强制所有操作先经过 Agent。

### 6.2 R08：总状态必须能表达停止与部分失败

提取线程返回结构化汇总，统一供日志、状态栏和完成通知使用。至少包含计划、尝试、成功、失败、跳过、未执行数量，以及是否用户停止、各项导出是否完整。不得只在循环末尾无条件写“提取流程已完成”。

| 条件 | 建议结果 |
|---|---|
| 无输入 PDF | 未执行：未发现 PDF |
| 所有要求的步骤成功，或复用的既有结果完整 | 全部成功 |
| 有可用结果，同时存在处理失败或必需导出不完整 | 部分成功；列出需重试项 |
| 用户请求停止且任务结束 | 已停止；列出已保留结果与未执行数量 |
| 没有可用结果并发生失败，或任务无法初始化 | 失败；列出可操作原因 |

“复用既有结果”单列，不重复计成新提取成功。备份清理警告与可导入文件导出失败分开：前者不一定使主要产物不可用，后者必须影响“产物完整”结论。发出完成信号、关闭数据库和恢复按钮时，不能把 cancelled 或 error 再改成 success。

**产物位置。** 原图片与数据库继续保留在用户选择的 PDF 输出目录。本轮以界面总状态、日志和完成通知为准。若已有运行报告设施，把同一份结构化汇总写进去；没有现成设施时，不要为这一轮新建 `run_reports/` 产品面。研究者需要的是“这次是全部成功、部分成功、已停止还是失败”，不是再多一套报告格式。

### 6.3 R08、R13：复核和导入动作准确命名

机器接受、人工通过、标记可导入和实际加入标注项目分别展示。“仅 accepted”改为“仅机器筛选通过”；“当前筛选全部设为可导入/通过”建议改为“将当前筛选结果标记为可导入”，并明确“仅更新复核标记；图片尚未加入 2D 项目，不生成训练标签”。

“标记可导入”仍可能代表研究者的复核决定，不能为了改名字把它降成另一个不相干的“待导入”状态。保留人工拒绝和需裁剪记录的现有保护；预览可更新条数、保留条数及筛选范围。实际导入使用独立动作和明确的目标项目。

来源预览把 `conf=`、`refs=`、复核原码改为可读标签，内部引用 ID 放在展开详情。未知评分显示“未提供”，不能把缺失值默认为 0 后解释成低质量。评分保留原始可追溯值；不统一改成百分比或“高可信”，除非该分数定义和校准依据支持概率解释。说明模型评分用途，不当作分类学事实的可靠度。

## 7. 体验建议与尚未证实事项

以下保留在设计范围内，但不与已确认的写入问题混为一谈。

| 项目 | 当前证据与边界 | 预计方法与验收重点 |
|---|---|---|
| 导出可停止 | 取消按钮确实被移除；已有数量进度和对象名称 | 先确认三类导出后端可在安全边界停止，再增加协作式取消。禁止强杀线程；最终汇总不能引用不完整数据集 |
| 导出完成打扰 | 成功后自动打开目录并弹窗已确认；是否打扰属于体验判断 | 保留结果数量、格式、目录；提供显式“打开文件夹”，减少重复通知。失败与部分完成仍需可见 |
| 长任务反馈统一 | 多个工作流各有反馈实现；未逐一运行 | 统一“阶段、对象、已完成量、停止状态”的呈现规范，复用各后端真实能力；不虚构进度百分比或“可安全停止” |
| 专家删除流程 | 已有详细确认与当前项目引用清理，尚未证明存在功能缺陷 | 先评估现有预览是否足够；明确磁盘模型和当前项目引用影响。不能承诺能查全未打开项目的引用或擅自简化保护 |
| Blink 名称 | 子部位专家、Blink、收缩工具名并存 | 面向操作用“子部位专家（Blink）”，保留“收缩起始框”等具体工具名称；不把不同动作改成一个模糊名字 |
| TIF 存储表 | Role、working_edit、dry-run 等为外部报告提出的线索，未逐项核查表格显示 | 核对后统一“文件用途、受保护原因、清理预览、可释放空间”；清理只能指向已允许清理的派生产物，不暗示删除标本 |
| TIF 核验按钮提示 | 报告提出提示语与实际按钮名不一致，需全入口核对 | 提示直接引用实际按钮名称，覆盖整标本、部位和重切片，避免教用户找不存在的按钮 |
| TIF 关闭提示 | 环境变量英文提示与触发路径尚未完整核实 | 主消息解释关闭原因、恢复入口和是否需重启；环境变量命令放“技术详情”，不隐藏真实失败 |
| 未知值和漏译 | 画布英文框后缀、Material 自译及 TIF 术语已见源码 | 区分“未提供”“未选择”“未知”“不适用”，不全局替换为同一词；技术标识与研究名称保留 |
| 本地配置的 Git 隔离 | 仅见未跟踪的运行配置文件；未跟踪不等于已泄露，也不证明凭据内容 | 后续单独核查忽略规则与发布过滤，只检查路径规则，不把真实配置内容写入文档。此项不属于 UI 修补 |

新增导出取消若需要暂存，使用目标导出目录内独立运行暂存区，并在成功收尾后发布最终文件。只清理该次运行明确拥有的暂存文件，不能删除既有用户输出。若目标格式尚不支持安全停止，先准确提示处理阶段，不提供假取消按钮。

## 8. 兼容性、恢复与实施边界

- **纯显示修改：** R02、R03、R04 的状态显示、R13 文案应读取现有数据，不重写标注、分类名称、材料 ID 或已有训练真值。2D 与 TIF 使用各自准入规则，不能跨格式套用一个布尔值。
- **行为修改：** R01 的 SAM 生成状态、R10 的提交保护、R14 的撤销恢复、R06 的项目入口、R08 的任务汇总均涉及实际行为，应独立记录和验证，不能宣称整轮都是“只改 UI”。R01/R10 与 R14 分开回归。
- **格式与版本：** 优先沿用现有 JSON/SQLite 容器及 `training_truth_v1`。第一轮 SAM 草稿复用已有 AI 来源，不增加新枚举，因此不把外层项目格式版本或来源契约当作本轮必改项。若后续批次新增来源枚举，即使不更改外层项目格式版本，也必须验证旧版打开行为：旧版应明确拒绝或排除不识别来源，不能静默把新草稿降回历史人工标注解释。
- **历史记录：** 不批量重标旧 SAM 来源，不自动降级旧真值，不改已有模型权重，不重跑训练，不自动迁移或清空 `_startup`。未来若需要维护性迁移，另给预览、备份、报告和恢复设计。
- **科学含义：** 状态修复改变的是程序如何呈现与接受结果，不重新解释解剖结构或分类结论。新增结果的训练准入行为会改变，需要在实施说明中明确“生成后还要复核”。
- **输出与临时文件：** 设计稿位于本目录。PDF 本轮以界面总状态为准，不强制新增运行报告目录。2D 标注继续由当前项目存储管理，TIF 真值继续使用既有项目 sidecar 和核验服务。编码验证仅用 `.tmp_validation/`，结束后清理临时验证产物。
- **发布边界：** 本稿按用户要求在开发仓库留档。不同步公开库，不更新 TaxaMask 版本号或 GitHub Release，不修改功能代码。未来公开同步仍按既有审查边界进行。

## 10. 验收矩阵

本节是**计划执行**的验收，不是已通过的测试记录。优先扩展现有行为测试，文案小改不为凑数量编写逐字符串镜像测试。以下程序验证均用可重复的示例数据，不使用真实研究标本来证明算法正确性。

| 场景 | 必须看到的结果 | 建议方式或现有测试入口 |
|---|---|---|

## 11. 留档时实际完成与后续记录方式

0.1 完成：读取两份巡检意见，追查上述关键函数与状态契约，形成问题表、推荐方案、兼容性约束和验收矩阵。

0.2 完成：根据第二次独立复核收紧实施约束（SAM 来源、首屏状态分层、批次拆分、启动项目身份、TIF 预测用词、PDF 报告范围），并按用户要求在开发仓库留档。没有运行 TaxaMask 实际点击验收，没有执行专项自动测试，没有修改功能代码。

未来实施时按编号记录“采用方案、修改文件、实际验证、已知限制、完成日期”，保留本稿提出时的证据边界。未验证的条目不得直接改成“已修复”，未运行的测试不得计入通过数量。遇到与本稿不同的运行证据时，补充更正理由，不把原推测伪装成已发生的事实。
