# TaxaMask v2.5.0：TIF 存储分层、按需物化与智能体清理闭环

发布日期：2026-08-24

`v2.5.0` 是一次 TIF/CT 大体积存储架构中版本升级。它让标签体按实际范围使用紧凑类型，让 nnU-Net 只生成当前任务真正需要的工作格式，并把占用盘点、清理计划、智能体解释、可恢复隔离和审计删除串成一条受控链路。

## 对研究工作流的直接变化

- 标签体不再一律使用 `uint16`。程序根据标签 ID 范围选择最小安全无符号整数类型，并在写入前拒绝溢出；常见少量材料标签可使用 `uint8`，不改变标签 ID 含义。
- nnU-Net v2 由后端按需生成 NIfTI，不再默认同时保留 OME-TIFF、NRRD、MHA 和 NIfTI 多套训练副本。其他后端仍可通过公开契约声明自己需要的格式。
- 相同内容使用稳定资产身份和内容寻址缓存复用；文件系统允许时使用硬链接，避免重复复制同一训练输入。
- 大型训练或预测启动前先估算输入、物化和临时空间峰值；空间不足时在外部后端启动前停止，避免磁盘写满后留下半套工作集。
- 工作台新增“分析占用、生成清理计划、交给内嵌智能体、打开最新报告”四个入口。清理计划会自动重新扫描，不依赖研究者记住上一次分析状态。

## 清理安全边界

存储按恢复价值分为 L0 到 L3。源 TIF、项目权威数据、`manual_truth`、模型权重、实验合同和未登记历史文件默认受保护；自动计划只纳入已经登记、身份核验通过且能够重建的缓存。

清理生命周期是：先生成 dry-run 计划，再移动到可恢复隔离区，经过宽限期后才最终删除。研究者可以在隔离期运行标注、训练或预测来确认项目仍正常；最终删除必须精确确认 plan ID。若明确要求提前越过宽限期，程序还会记录 `grace_period_overridden` 审计事件。

内嵌智能体负责读取最新报告、解释哪些空间可释放、说明保护项，并在研究者明确授权后执行受控清理。报告不是让研究者自行寻找并删除目录的操作清单。未经授权，智能体只能分析和建议。

## 实测结果与适用边界

在一个真实本地 TIF 项目中，18 个旧 `uint16` 标签迁移为 `uint8`，再清理 8 个已核验可重建缓存，累计释放约 132.65 GB。清理后项目 SQLite 完整性正常，26 个 specimen 仍可访问，11 份模型清单及其外部 checkpoint 均存在，研究者完成实际使用确认。

这个数字只描述该项目的输入规模和历史副本结构，不是所有项目都能节省 132.65 GB，也不是固定压缩比例。训练仍会生成后端必需的工作集、预处理结果和模型输出；本版本减少的是不必要的长期多格式副本和可复用内容的重复写入。

## 数据、模型与科学结论边界

- 本版本不自动删除源 TIF、`manual_truth`、模型权重或实验合同。
- AI 预测仍先进入待复核层，不能因为存储升级而成为训练真值。
- 本版本提升的是软件存储效率、恢复能力和清理可审计性，不证明模型的生物学准确率提高。
- 正式发布仓不包含用户 TIF/CT、项目数据库、标注数组、模型权重、日志、API 配置或本地运行产物。

## 升级与验证

更新后请完整退出并重启 TaxaMask。已有 TIF 项目可以继续打开；旧标签迁移和缓存清理均应先生成报告和 dry-run 计划，再按项目逐批执行。建议先隔离缓存，实际打开项目并完成一次代表性的标注、模型选择或预测复核，确认无误后再做不可逆删除。

自动化门禁包含独立的 `v250_release_audit` 存储与 TIF 链路冻结套件，本地冻结运行 89 项全部通过；上一版本的 `v2410_release_audit` 数据完整性基线 366 项也全部通过，其中 12 项按 Windows 平台条件跳过。默认全量入口完成 2,016 次测试调用，对应 1,989 个唯一 test ID，27 次重复来自既有分组的交叉覆盖。正式发布还要求同一提交通过 Windows、Ubuntu、macOS Python 3.12、Embedded Agent Center 和 Paper Distill Skill bundle 检查。自动化测试证明代码路径和保护边界按设计工作，不代替真实标本的人工解剖学复核。
