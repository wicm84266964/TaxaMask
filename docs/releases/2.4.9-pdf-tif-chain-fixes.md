# TaxaMask v2.4.9：PDF 文件名与 TIF 标注链路修复

发布日期：2026-08-23

`v2.4.9` 是 v2.4 系列的小型修复版本。它修复 PDF 图像进入 2D 工作台时的空白字符文件名问题，以及 TIF 工作台在真值提升回调和模型草稿导回阶段暴露的两个连续运行断点；不修改项目数据格式、标注算法或训练模型。

> 发布记录状态：`v2.4.9` tag 已固定在提交 `1756e43f5f01fcc9742dd28c27f3b0e62fc5fe5f`，并受 GitHub tag 更新/删除规则保护。本文后半部分的“发布后全面复核”是后续审计记录；其中列出的候选修复不在 `v2.4.9` tag 内，也不会出现在任何基于该 tag 生成的归档中，不能解释为该版本已经包含。

## v2.4.9 tag 内的 PDF 到 2D 修复

- PDF 图像导出文件名会使用附近图注生成可追溯名称。旧逻辑允许制表符、换行等空白字符通过清洗，但只把普通空格替换为下划线，可能在 Windows 文件创建或后续 2D 工作台导入时失败。
- `v2.4.9` 统一把连续空白规范化为单个下划线，继续保留 PDF 文件名前缀、页码、图序号和图像内容哈希。
- 该修复只改变新导出图像的文件名，不改写提取出的图注正文、PDF 文本块或已有项目记录。

## v2.4.9 tag 内的 TIF 真值提升线程修复

- TIF 标注工作流控制器改为 Qt `QObject`，正常由 TIF 工作台创建时归属工作台 GUI 线程。
- 后台保存或真值提升 worker 完成后，连接到控制器的方法由 Qt 按对象线程归属排队处理，避免从 worker 线程直接刷新控件导致 Windows access violation。
- 真值提升入口仍显示确认对话框；该版本没有增加自动接受，也没有改变训练只读取已核验 `manual_truth` 的门禁。

## v2.4.9 tag 内的 TIF 模型草稿导回修复

- 用户执行“复制最新模型草稿”时，工作台在把 `model_draft` 复制到 `working_edit` 前释放当前加载的体数组，并等待相关文件句柄关闭。
- 该处理修复了 Windows 因开放 memmap 占用 `working_edit` 目标目录而出现的 `WinError 5`。
- 数组释放超时或复制抛出异常时，`v2.4.9` 会尝试重新加载当前 specimen 并显示警告；这一失败路径只能恢复磁盘上已保存的状态，不承诺保留尚未保存的内存编辑。
- 在正常、互相独立的标签路径布局中，回归测试确认复制目标是 `working_edit`，已有 `manual_truth` 内容保持不变。发布后审计发现别名路径仍需额外保护，详见下文，因而不把这一结果表述为对所有异常项目布局的绝对保证。

## 数据影响与兼容性

- 安装或启动 `v2.4.9` 不会自动迁移项目数据库，也不会自动重写 TIF/CT 源数据、标签数组、训练数据、模型权重、API Key 或用户配置。
- “复制最新模型草稿”是显式写操作：用户确认执行后会有意替换当前 specimen 的 `working_edit`；它不是只读操作。
- `manual_truth` 是内部训练标签角色。正常流程中的模型预测先进入草稿或工作编辑层，只有保存并经过显式确认后才提升为训练真值。
- `v2.4.8..v2.4.9` 的正式提交只增加或修改源码、测试、发布文档与 `CITATION.cff`，没有加入本地研究项目、PDF/TIF 原始数据、数据库、标注数组、模型权重或实验产物。该结论描述发布提交内容，不代表对用户运行目录或外部文件的扫描保证。
- 已有 2D 和 TIF 项目不需要格式迁移。

## 发布后全面复核，不属于 v2.4.9 tag

2026-08-23 的发布后全面复核进一步识别并覆盖以下边界。对应修改位于后续 `main` 候选改动中，只有进入新的提交和版本后才可视为正式修复：

- PDF 数据库与命名空间：PDF 范围标识与 SQLite `UNIQUE(file_path)` 使用的精确身份保持一致；每次提取在数据库提交前使用独立运行命名空间保存 figure/review 产物，避免不同 PDF、名称清洗碰撞或失败重试互相覆盖。
- PDF 提取事务：数据库提取在提交前失败会回滚，并且只清理本次运行创建的产物；无论成功或失败，PDF 文档均在 `finally` 中关闭。
- PDF import-ready 投影：导出采用 staging、publish、rollback 文件系统事务。投影失败会明确返回 `partial_success`，已经提交的数据库提取结果保持不变；恢复操作只重试 import-ready 投影，英文和中文界面都会说明部分成功状态及重试方式。回滚清理不完整时保留独立恢复目录，避免把仍需人工处置的文件误删。
- Agentic PDF 状态传播：`tools/agentic/extract_figures.py` 不再把 `partial_success` 计为通过，而是报告 `failed_projection`、数据库已提交状态和恢复目录，并把整次运行标为 `partial`；完整成功和已完成提取的正常恢复仍保持通过语义。
- PDF 清理边界：旧版或过期产物仅在身份无歧义时清理；大小写差异可能指向同一路径时保守保留，清理权限错误只记录警告，不把已提交提取误判为失败。
- TIF 路径身份：`working_edit`、`manual_truth`、part/reslice truth 和草稿源按平台真实路径身份及祖先/后代重叠关系检查。保护覆盖底层 sidecar 复制、完整真值提升、部位真值提升、重切片真值提升和模型草稿导回；对 macOS 常见的大小写不敏感文件系统，即使目标子路径尚不存在，也通过已存在物理祖先的文件身份识别大小写变体或目录别名，同时保留大小写敏感文件系统上合法同级目录的区分。
- TIF 复制事务：体数组替换、内存项目状态、SQLite 保存及失败回滚协同执行；复制到 `working_edit` 不推进 `manual_truth` 谱系，保存失败不能留下新数组配旧数据库记录。数据提交成功但旧回滚备份删除失败时不撤销已提交数据，而是在当前 manager 实例的有界告警记录及日志中暴露清理错误，供后续人工清理。
- TIF 失败恢复：复制前的未保存状态在释放、复制或重新载入失败以及重复尝试后仍可恢复；恢复内容包括脏切片、修订号、撤销/重做历史、工具和材质选择。空恢复快照不会覆盖已有的待恢复状态。
- TIF 保存与自动保存：保存元数据必须成功完成后才清除 dirty 状态。自动保存等待超时会保留仍在运行的线程、worker 和任务引用，并阻止后续同步保存或项目清理，不能把“尚未结束”误当成“已经完成”。
- 主窗口项目生命周期：关闭 TaxaMask 或切换到另一项目时，尊重 TIF 未保存提示中的取消选择；活动的 TIF 保存、真值提升、导入、后端线程和 task manager 任务都会阻止项目被替换。
- 网格测试导航：网格导出可见性回归用例改为先进入“结果对比”页，再检查切片/体视图中的入口可见性，使测试与 v2.4.6 已记录的界面迁移一致；这只是测试导航修正，不是产品布局回归或布局改动。

发布后审计入口初建时包含 72 个精确、唯一且可加载的 test ID；这是审计过程中的中间快照，不是后续版本的冻结计数。该入口后来扩展并以 `v2410_release_audit` 名称进入 `v2.4.10` 候选，旧名 `v249_post_release_audit` 仅作为历史兼容别名保留。最终测试范围和数字以 `docs/releases/2.4.10-pdf-tif-integrity_zh.md` 为准；发布时的历史 1,632 个唯一 test ID 仍只描述 `v2.4.9` tag，不能拿后续版本数字替换。

```bash
python scripts/run_validation_suite.py --suite v249_post_release_audit --timeout 300
python -m unittest tests.test_validation_suite_script
git diff --check
```

本轮候选改动在 Windows `taxamask` Conda 环境（PySide6 6.10.1、torch 2.7.1）执行中间审计套件，得到 `Ran 72 tests in 5.759s, OK`，无失败或跳过。此前 65 项中间基线曾连续得到 `Ran 65 tests in 5.586s, OK` 和 `Ran 65 tests in 5.393s, OK`；这些数字只说明审计扩展过程，不能代替 `v2.4.10` 的冻结测试结果。三个操作系统的结果仍应以包含后续修复提交的新 Actions 日志为准。

该 CI 配置只能验证包含这些后续改动的新提交；它不改变 `v2.4.9` 已发布 tag 的测试覆盖事实。

## 结果边界

本版本及发布后审计处理的是软件工作流连续性和数据保护边界。它们不证明由少量样本训练的定位模型已达到生物学准确性，也不把智能体模拟 UI 点击或机器裁决实验标注表述为人工或独立专家真值。

- 上述候选修复不在不可变的 `v2.4.9` tag 中，必须经过后续提交、跨平台 CI 和新版本发布后才能交付给用户。
- 当前候选修复证据来自 Windows 本地环境以及合成、单元和 UI 回归测试；新提交的 macOS/Linux 结果需等待 CI。
- `partial_success` 有意保留已经提交的 PDF 数据库提取结果，import-ready 导出需在故障排除后重试。
- 对过期产物的 warning-only 清理策略可能留下派生文件，需要用户在权限恢复后手动清理。
- TIF 未保存编辑的待恢复快照只存在于当前进程内；进程崩溃或退出后不能把它当作持久恢复日志。发布后审计的早期候选曾只在 manager 内保存提交后清理告警，`v2.4.10` 冻结候选随后把这类维护告警写入项目内有界 sidecar；最终行为以 `docs/releases/2.4.10-pdf-tif-integrity_zh.md` 为准。
- `manual_truth` 是训练数据角色和工作流门禁，不是操作者身份认证、人工来源证明或专家质量背书。
- 这些测试不建立生物学准确性，也不证明机器标注与人工真值等价。

## 升级说明

使用 `v2.4.9` 后请完整退出并重启 TaxaMask。Windows 用户继续双击 `启动TaxaMask.bat`；WSL/Linux 用户使用 `启动TaxaMask.sh`。已有项目、TIF 工作体和已保存标注无需迁移或重新导入。发布后审计列出的候选修复应等待后续正式版本，不应通过重新下载同一 `v2.4.9` tag 期待获得。
